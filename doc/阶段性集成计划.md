## 4. 推荐合并顺序与命令

顺序原则：**先合互不重叠的，把冲突集中的那条放最后**。

```powershell
# 1) 从 main 建集成分支（不动 main 本身）
git switch -c integrate/stage1 main

# 2) 先合两条零冲突的（顺序可互换）
git merge --no-ff --no-edit origin/codex/scaler-handoff
git merge --no-ff --no-edit origin/feature/audio-ctrl

# 3) 到这里先验证一次（TD 全流程 + 上板，见第 6 节）

# 4) 最后合冲突最多的那条：先预览不提交
git merge --no-commit --no-ff origin/codex/key3-zoom-only
#    解决下面第 5 节的 2 个文件后：
git add -A && git commit

# 5) 再验证一次，通过后打阶段性 tag
git tag -a stage1-2026-10-10 -m "阶段性集成：OSD + 音频/音画联动/波形 + 缩放"
```

> 想中途放弃：合并过程中 `git merge --abort`；已提交后 `git reset --hard backup/main-2026-10-10`。**任何一步都不会丢源码**。

### 5.2 `SD/sd_card_bmp.v`（5 块，全部是"两个功能并存"，不是二选一）

| 块 | 我方（HEAD） | 对方（key3-zoom） | 合并做法 |
| --- | --- | --- | --- |
| 1 | `AUTO_TICKS` localparam + 两条 `assign write_en/write_data` | `assign state_code` + `generate if (ENABLE_ZOOM)…end else…endgenerate`（else 分支里已经含等价的 `write_en/write_data`） | **保留我的 `AUTO_TICKS`**；采用对方的 generate 块；**删掉我那两条模块级 assign**（否则同一根 wire 被重复驱动） |
| 2 | `.DEBOUNCE_MS (DEBOUNCE_MS)`（参数化） | 新增第 3 个消抖实例 `u_key_zoom`，写死 `.DEBOUNCE_MS (20)` | 两个都留；`u_key_zoom` 的 `.DEBOUNCE_MS` 也改成 `DEBOUNCE_MS` 保持一致 |
| 3 | 2 行 `audio_track_*` 复位 | 6 行 `zoom_*` 复位 | **两边都留**（共 8 行） |
| 4 | 提交那一刻更新 `audio_track_idx/toggle` | `zoom_displayed <= zoom_loading;` | **两边都留** |
| 5 | "手动下一张"分支，条件用 2bit 计数器 `(next_req_pending != 2'd0)` | 在手动分支**之前**插了一条"缩放重载"分支；它的手动分支用 1bit 的 `next_req_pending` | 优先级链改成：①首图 ②**缩放重载（对方）** ③**手动下一张（我方 2bit 写法，含 `next_req_pending <= next_req_pending - 2'd1`）** ④自动轮播 |

**块 5 是唯一需要动脑的**：必须保证同一时刻只有一个分支生效，且 `next_req_pending` 的递减只发生在"手动下一张"分支里。合完要复测连按（连按 3 次应连切 3 张）。

### 5.3 不要做的事

- ❌ 不要用 `git checkout --ours/--theirs` 整侧取舍 —— 那是最容易丢代码的操作；
- ❌ 不要手工硬合 `.al` 工程文件（本次它是自动合并成功的）。若某个功能合后在工程里看不到，**在 TD 里把缺的源文件重新"添加到工程"**，TD 会自动重排编译顺序；
- ❌ 不要对已推送到远程的公共分支用 `rebase` 改写历史。

## 8. 长期建议（避免以后再花时间解冲突）

1. 阶段性集成通过后，**所有人都从集成分支/新 main 拉新分支**继续开发，不要再在旧分支上长期分叉；
2. **公共分支只 merge、不 rebase**；
3. 每周一次集成节点，合完即验证、验证通过即打 tag；
4. 每个功能分支合之前，先 `git merge main`（把自己的分支更新到最新 main）再提 PR，把小冲突在自己的分支上解决掉。
