# 数码管状态码对照表

板上 6 位数码管里，第 6 位（`seg_scan` 的 `seg_data_5` 那一位）显示的是
`bmp_read` 的内部状态码 `state_code`，其余位灭。调试时先看这一位，
比看波形快得多。

## 状态码含义

| 码 | `bmp_read` 状态 | 含义 | 常见现象 |
| --- | --- | --- | --- |
| 0 | 复位 / `ST_IDLE` 初值 | 系统复位中，或 SDRAM/卡还没就绪 | 上电瞬间、PLL 未锁定、TF 卡没插好 |
| 1 | `ST_IDLE` | 空闲，等 `scan_start` 或 `load_start` | 正常待机；长时间停在 1 说明没收到扫描/加载请求 |
| 2 | `ST_SCAN` / `ST_LOAD_HDR` | 正在扫描扇区找 `BM` 标识 / 正在读文件头 | 扫描阶段；一直停在 2 说明卡里没有合法 BMP，或文件头不是 640×480/24bit |
| 3 | `ST_LOAD_WAIT` | 已发起写帧请求，等帧缓存写口应答 | 一直停在 3 说明 `frame_read_write` 没应答（A 的模块） |
| 4 | `ST_LOAD_DATA` | 正在读像素数据并写入帧缓存 | 正常出图过程中；一直停在 4 说明数据流卡住 |

## 排查顺序

1. **停在 0**：先查复位与 PLL 锁定位（`rst_all` 是三个 lock 的与），再查 TF 卡接触；
2. **停在 1**：外部没触发扫描/加载 —— 看 `display_valid` 和按键通路；
3. **停在 2**：卡里没有能被识别的 BMP。用 `scripts\sync_to_sd.py` 重新同步
   （普通删除会留下物理残留，FPGA 是按扇区扫描的，会读到旧图或死机）；
4. **停在 3**：帧缓存写口没应答，找 A；
5. **停在 4 很久**：BMP 文件损坏或扇区读失败，换图重试。

## 按键与轮播的观察点

数码管只有 4bit 状态码，看不到按键与轮播状态，需要靠画面判断：

| 操作 | 预期现象 |
| --- | --- |
| 按 key1（手动下一张） | 画面换到下一张；连按 3 次应连切 3 张，不丢 |
| 按 key2（轮播开关） | 画面右下 OSD 面板文字在 `PLAY n` 与 `AUTO n` 之间切换 |
| 轮播开启 | 每 3.0s ± 0.3s 自动切下一张（`AUTO_INTERVAL_MS = 3000`） |
| 切换音频 | 换图瞬间音频淡出约 20ms、换段后再淡入，听不到"啪"声 |
