## 1. 全局约定

### 1.1 命名规范

| 类别           | 规则                               | 示例                    |
| -------------- | ---------------------------------- | ----------------------- |
| 时钟           | 功能名 _clk                        | sd_card_clk / video_clk |
| 复位           | 高有效：rst；低有效：rst_n         | rst_all / rst_n         |
| 低有效信号     | 后缀 _n                            | sd_ncs                  |
| 有效使能       | 后缀 _en / _valid / _req           | App_wr_en               |
| 完成与应答     | 后缀 _finish / _ack                | write_req_ack           |
| 本文档新增模块 | 输入 I_xxx、输出 O_xxx、内部 S_xxx | I_i2s_BCLK              |

约定如下：

- **新增代码统一用 I_/O_/S_ 前缀**；
- 不改动官方已有模块的端口名，如需改动应在自己分支中修改接口文档并及时提交。
- 跨模块连接的信号名，由被连接方（消费方）负责命名。

### 1.2 复位极性

工程同时存在两种极性的复位：

| 信号           | 极性             | 位置                           |
| -------------- | ---------------- | ------------------------------ |
| rst_n          | **低有效** | 仅顶层端口（板载按键 A2）      |
| rst / rst_all  | **高有效** | 除 seg_scan 外的所有内部模块   |
| seg_scan.rst_n | 低有效           | 全工程唯一直接用板载按键的模块 |

约定：

- 新增模块的复位端口一律命名为 rst（高有效），**异步复位、同步释放**；
- 任何模块都不允许直接用顶层 rst_n，必须用 rst_all；
- rst_all = （~rst_n）|（~sys_pll_lock）|（~video_pll_lock）|（~audio_pll_lock），**三个 PLL 全部锁定前全系统保持复位**，这是上电防抖（POR）机制，不得绕过或简化。三个 lock 分别来自 sys_pll.extlock、video_pll.extlock、PLL_HDMI_AUDIO.extlock（2026-10-07 补齐）。

### 1.3 时钟域与约束名对应

见第 2 节。约束文件里的时钟名必须与本表完全一致，否则时序分析会漏路径。

### 1.4 数据格式与字节序

| 项目       | 约定                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 像素格式   | RGB888，打包为 {R, G, B}，R 在高位                                   |
| SDRAM 字宽 | 32 bit，**一个像素占一个字，像素数据放在 [31:8]，[7:0] 保留**  |
| 视频读出   | video_delay 的输入接的是 video_read_data[31:8]（高24位）             |
| BMP 输入   | 640×480、24 位非压缩，每行 1920 字节，行尾 4 字节对齐               |
| 帧大小     | FRAME_PIXELS = 307200；缓冲区 0 起始地址 0，缓冲区 1 起始地址 307200 |

### 1.5 跨时钟域规则

1. 禁止把某个时钟域的寄存器输出直接送到另一个时钟域的组合逻辑或时序逻辑；
2. 单比特控制信号：打两拍同步后再使用；
3. 单比特脉冲跨域：按 1.6 节 D 类（toggle）方式传递；
4. 数据流跨域：必须经过异步 FIFO；
5. 任何跨域都必须在 timing.sdc 中体现（set_clock_groups），仿真时注意检查跨域时序。

### 1.6 四类握手协议

**A 类 · valid/ready 数据流**
valid 与 data 必须同拍有效；valid 拉高后 data 必须保持，直到对端 ready 拉高的那一拍采样完成；valid 不允许中途撤销。

**B 类 · req/ack 事务请求**
请求方把 req 拉高并保持，直到采样到 ack 为 1；被请求方在准备好时给至少 1 拍的 ack。典型：write_req / write_req_ack，read_req / read_req_ack。

**C 类 · 电平使能 + 完成脉冲**
en 与 data 同拍给出，接收方在时钟上升沿采样；整段传输结束后给一个单拍的 finish。典型：write_en / write_data 配 write_finish。

**D 类 · toggle 跨域握手**
跨时钟域只传一位翻转电平，接收侧打两拍同步后异或得到单拍脉冲。典型：frame_write_finish（ext_mem_clk 域）→ frame_write_toggle_mem → sd_card_bmp 内部同步使用。

## 2. 时钟与复位总表（按官方例程填写）

### 2.1 时钟

| 时钟名          | 来源                | 频率       | 相位   | 约束名             | 主要使用者                                     |
| --------------- | ------------------- | ---------- | ------ | ------------------ | ---------------------------------------------- |
| clk             | 板载晶振（引脚 R7） | 50 MHz     | 0 度   | clk（period 20ns） | 三个 PLL 的输入、seg_scan                      |
| sd_card_clk     | sys_pll C0          | 100 MHz    | 0 度   | sd_card_clk        | TF 卡 SPI、sd_card_bmp、帧缓存写口             |
| ext_mem_clk     | sys_pll C1          | 125 MHz    | 0 度   | ext_mem_clk        | SDRAM 控制器、帧缓存读写调度                   |
| ext_mem_clk_sft | sys_pll C2          | 125 MHz    | 180 度 | -                  | SDRAM 采样移相                                 |
| video_clk       | video_pll C0        | 25.000 MHz | 0 度   | video_clk          | 视频时序、帧缓存读口、HDMI 像素口、I2S 接收    |
| hdmi_5x_clk     | video_pll C1        | 125 MHz    | 0 度   | hdmi_5x_clk        | TMDS 并串转换（5 倍像素时钟）                  |
| audio_mclk      | PLL_HDMI_AUDIO C2   | 12.295 MHz | 0 度   | audio_mclk         | I2S 测试音发生（目标 12.288 MHz，偏差 0.058%） |

时钟域关系（timing.sdc 已声明）：

- video_clk 与 hdmi_5x_clk 同源，设为 exclusive（互斥，不做互相之间的分析）；
- audio_mclk 与其余全部时钟设为 asynchronous（异步）；
- 其余时钟域之间**当前未做时序豁免**。这意味着任何新增的跨域路径都会在时序报告里暴露出来，不要私自加豁免。

### 2.2 复位

| 信号           | 极性                   | 来源                   | 覆盖范围                     |
| -------------- | ---------------------- | ---------------------- | ---------------------------- |
| rst_n          | 低有效                 | 板载按键（引脚 A2）    | 顶层端口，仅供 seg_scan 使用 |
| audio_pll_lock | 高有效（1 表示已锁定） | PLL_HDMI_AUDIO.extlock | 音频 PLL 锁定指示            |
| sys_pll_lock   | 高有效（1 表示已锁定） | sys_pll.extlock        | 系统 PLL 锁定指示            |
| video_pll_lock | 高有效（1 表示已锁定） | video_pll.extlock      | 视频 PLL 锁定指示            |
| rst_all        | **高有效、异步** | 由上面几个信号组合得到 | 除 seg_scan 外的全部模块     |

## 4. 跨模块接口表

### IF-01 按键到控制与切图（张淦森）

| 信号           | 方向           | 位宽 | 时钟域      | 说明             |
| -------------- | -------------- | ---- | ----------- | ---------------- |
| key1           | 顶层到被测逻辑 | 1    | 异步输入    | 板载按键，未消抖 |
| key2           | 顶层到被测逻辑 | 1    | 异步输入    | 板载按键，未消抖 |
| key_next_press | 内部           | 1    | sd_card_clk | 消抖后的单拍脉冲 |
| key_auto_press | 内部           | 1    | sd_card_clk | 消抖后的单拍脉冲 |

协议：C 类（单拍脉冲）。消抖由 sd_card_bmp 内部子模块完成（CLK_FREQ_HZ = 100 MHz，与时钟匹配）。

待确认：工程里还存在 ax_debounce.v（默认 FREQ = 50，即假设 50 MHz 时钟）。若它也被实例化，消抖时间会算错一倍。冻结前必须确认全工程只有一套生效的消抖实现。

### IF-02 TF 与 BMP 写数据到帧缓存写口（景为一、李宇良）

生产者 sd_card_bmp（sd_card_clk 域）；消费者 frame_read_write 写口。

| 信号                | 方向   | 位宽 | 时钟域                | 说明                                             |
| ------------------- | ------ | ---- | --------------------- | ------------------------------------------------ |
| write_req           | B 到 A | 1    | sd_card_clk           | 请求写入一帧，B 类握手                           |
| write_req_ack       | A 到 B | 1    | sd_card_clk           | 应答，至少 1 拍                                  |
| write_en            | B 到 A | 1    | sd_card_clk           | 像素写使能，每个像素 1 拍                        |
| write_data          | B 到 A | 32   | sd_card_clk           | 一个像素占一个字，有效位 [31:8]                  |
| write_buf_idx       | B 到 A | 2    | sd_card_clk           | 写目标缓冲区号（0 或 1）                         |
| write_finish        | A 到 B | 1    | **ext_mem_clk** | 整帧写完成，单拍                                 |
| write_finish_toggle | A 到 B | 1    | sd_card_clk           | 上面这个信号经 toggle 跨域后的版本，B 侧只能用它 |

约定：写长度 write_len = 307200；写起始地址由 write_addr_index 选择 BUF0（地址 0）或 BUF1（地址 307200）。

### IF-04 帧缓存读口到视频时序（李宇良）

消费者 video_timing_data（发请求）与 video_delay（取数据），均在 video_clk 域。

| 信号            | 方向         | 位宽 | 时钟域    | 说明                               |
| --------------- | ------------ | ---- | --------- | ---------------------------------- |
| read_req        | 视频到帧缓存 | 1    | video_clk | 每帧开始前请求读一整帧（B 类握手） |
| read_req_ack    | 帧缓存到视频 | 1    | video_clk | 应答                               |
| read_en         | 视频到帧缓存 | 1    | video_clk | 逐像素读使能（来自 de）            |
| read_data       | 帧缓存到视频 | 32   | video_clk | 像素在 [31:8]，不是 [23:0]         |
| read_addr_index | 视频到帧缓存 | 2    | video_clk | 等于 disp_buf_idx，选择显示缓冲区  |
| read_len        | 视频到帧缓存 | 21   | video_clk | 固定 307200                        |

时序约定：video_delay 内部对 hs、vs、de 固定延迟 **21 拍**（读使能取第 18 拍），用于让 SDRAM 读延迟与像素输出对齐。**这个数字是接口的一部分**，任何人都不得单独改动；改了必须同时调整 video_delay 的抽头并重新仿真。

### IF-05 像素流到 HDMI 发射核（李宇良）

| 信号         | 方向     | 位宽 | 说明                            |
| ------------ | -------- | ---- | ------------------------------- |

| axis_s_valid | 到核     | 1    | 像素有效（经 1 拍延迟的 de）    |
| axis_s_last  | 到核     | 1    | 行尾与帧尾标志                  |

待确认三项：

1. axis_s_ready 已引出但悬空，等于假设核永远 ready。上板若出现撕裂或丢行，第一个要查的就是这里。
2. video_rgb_to_axis_640x480.v 中 O_video_last 的比较值是 638 而非 639，实测该信号恒不拉高，需修（已定位，待确认后修改源码）。
3. HDMI 发射核参数是接口级常量，改动等于换视频格式，必须走变更流程。当前值：HTOTAL 800、HSA 96、HFP 16、HBP 48、HACTIVE 640、VTOTAL 525、VSA 2、VFP 10、VBP 33、VACTIVE 480、VIC 1、音频 48 kHz。
