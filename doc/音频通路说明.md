## 1. 链路总览

```
                                 audio_mclk 域(12.295MHz)                video_clk 域(25MHz)
```

## 2. 数据格式

| 项目 | 约定 |
| --- | --- |
| ROM 数据 | 8bit **有符号** 线性 PCM（0x00 为静音，0x80 = -128，0x7F = +127） |
| 素材采样率 | 8 kHz |
| 每段长度 | 12288 样点 = 1.536 s |
| 段数 | 4 段，段偏移 0 / 12288 / 24576 / 36864 |
| ROM 深度 | 49152（= 4 × 12288），宽度 8 |
| I2S 帧率 | 48 kHz（LRCK = MCLK/256），**与素材采样率无关，必须恒定** |

---

## 3. 为什么必须保持 48 kHz 帧率（最容易踩的坑）

HDMI 音频核用 ACR 包告诉显示设备"音频采样率和视频时钟的关系"，
而 `audio_arc_calculate` 是靠**数 `audio_valid` 的速率**来算 `acr_cts` 的：

```
AUDIO_DIV = ACR_N >> 7 = 48        每 48 个 audio_valid 出一个 ACR 包
acr_cts   = 两次 ACR 之间 video_clk 的拍数 ≈ 25MHz / 48kHz × 48 = 25000
```

所以只要送进 I2S 的帧率不是 48 kHz，`acr_cts` 就会算错，HDMI 端可能
直接不出声。**结论：任何音频素材都必须以 48 kHz 的帧率送入 I2S。**

本工程的做法：播放器内部保留与 `hdmi_audio_tone_i2s_64fs` 完全相同的 I2S
时序（BCLK = MCLK/2、LRCK = MCLK/256、每声道 64bit），8kHz 素材靠
**6× 零阶保持**上采样到 48 kHz 帧率：

- 每 6 个 48 kHz 帧取一次新的 ROM 样点（同一值连续出现 6 帧）；
- 48kHz/8kHz = 6.0034 而不是整数，所以推进节拍用分数累加器
  `acc += SRC_HZ×256; acc ≥ MCLK_HZ 时推进并相减`，得到精确的 8.000 kHz，
  连续帧数在 6 与 7 之间摆动（S6 用例就是按这个判的）。

## 4. `audio_rom_player` 端口

| 端口 | 方向 | 位宽 | 时钟域 | 说明 |
| --- | --- | --- | --- | --- |
| `I_mclk` | in | 1 | — | 12.295MHz 音频主时钟（PLL_HDMI_AUDIO C2） |
| `I_rst` | in | 1 | — | 高有效（`rst_all`），异步复位同步释放 |
| `I_track_idx` | in | 2 | 源：sd_card_clk | 当前音频段号（稳定电平，内部打两拍） |
| `I_track_toggle` | in | 1 | 源：sd_card_clk | 换段时翻转，内部三拍取异或边沿 |
| `I_rom_data` | in | 8 | audio_mclk | ROM 读数据 |
| `O_rom_addr` | out | 16 | audio_mclk | ROM 读地址 |
| `O_i2s_BCLK` | out | 1 | audio_mclk | = MCLK/2 = 6.144MHz |
| `O_i2s_LRCK` | out | 1 | audio_mclk | = MCLK/256 = 48kHz |
| `O_i2s_DOUT` | out | 1 | audio_mclk | 串行数据，样本在 [63:40] |

关键参数：`MCLK_HZ=12295000`、`SRC_HZ=8000`、`SEG_SAMPLES=12288`、
`RAMP_FRAMES=960`（20ms）、`LOOP_EN=1`（播完循环）。

淡入淡出：切段时用 8bit 增益斜坡，24bit 样本 = `(signed8 × gain) << 8`，
一个 8×8 乘法（≤1 个 DSP）。复位后也从 0 淡入，避免上电爆音。

---

## 5. 资源预算

| 项目 | 占用 |
| --- | --- |
| `AUDIO_SPEECH_ROM` | 8bit × 49152 = 48KB → 12 / 16 个 32Kb BRAM 块（75%） |
| 乘法器 | 8×8 增益乘法 1 个（DSP 余量 29，够用） |
| 逻辑 | 播放器本体以计数器/比较器为主，LUT 增量很小 |

若后续 BRAM 紧张，把素材改成 4 段 × 1 秒（`--seg-samples` 与
`AUDIO_SPEECH_ROM.ipc` 的 `depth_a` 同步改）即可降到 32KB / 8 块。

## 6. 换素材：三步

```powershell
# 1) 准备 4 段讲解录音（wav，采样率随便，脚本会重采样到 8kHz）
python scripts\wav_to_speech_rom.py seg1.wav seg2.wav seg3.wav seg4.wav `
    -o lab_ex5_i2s\src\user_source\hdl_source\team\audio_speech_rom.mif

#    没有素材时先用 demo 音打通链路：
python scripts\wav_to_speech_rom.py --demo `
    -o lab_ex5_i2s\src\user_source\hdl_source\team\audio_speech_rom.mif

# 2) TD 里重新综合（ROM 的初始化文件会自动重新读入）
# 3) 上板确认 4 段与 4 张图一一对应
```

每段超过 1.536s 的部分会被截掉，不足的补静音，两端各加 10ms 淡入淡出。

## 7. 波形叠加层接线（阶段 3，基础版稳定后再做）

`team/waveform_overlay.v` 已经实现，但**故意没有接进顶层**，因为它属于
"基础版不稳定不加新功能"的范围。接的时候按下面插一层：

```
video_delay → osd_overlay → waveform_overlay → video_rgb_to_axis_640x480
```

| 端口 | 接法 |
| --- | --- |
| `clk/rst` | `video_clk` / `rst_all` |
| `enable` | `display_valid` |
| `audio_valid` / `audio_sample` | `I2S_receiver` 的 `O_audio_valid` / `O_audio_left_data` |
| `hs_in/vs_in/de_in/rgb_in` | 用 `osd_overlay` 的 `hs_out/vs_out/de_out/rgb_out` |
| `hs_out/vs_out/de_out/rgb_out` | 接到 `video_rgb_to_axis_640x480` 的 `I_vs/I_de/I_rgb` |

窗口默认放在画面左上（x=64, y=16, 512×72），在 OSD 面板（y=380 起）上方，
不会覆盖 B 的字幕。所有输出与输入同延迟 1 拍，与 `osd_overlay` 的做法一致。
