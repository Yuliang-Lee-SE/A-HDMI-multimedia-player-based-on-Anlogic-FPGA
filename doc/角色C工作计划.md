## 3. 阶段安排

### 阶段 A：清场与骨架（第 1~2 天）

- 关闭 OI-04：确认全工程只有一套消抖实现，给出死代码清单交 A 从 TD 工程移除。
  结论：真正生效的是 `sd_card_bmp.v` 内的 `key_press_debounce`（100MHz / 20ms）；
  `SD/ax_debounce.v`（假设 50MHz）与 `key_remove_shakes.v` 都**没有被例化**。
- 建立 `doc/测试记录表.md`、`doc/状态码对照表.md`。
- 脚本参数化：打通 `run_regression.ps1`、`gen_test_patterns.py`。

### 阶段 B：真实音频出声（第 3~5 天）

先只做"出声"，不做联动，风险最低：

1. 用 `wav_to_speech_rom.py` 生成 4 段素材的 MIF；
2. TD 里把 `AUDIO_SPEECH_ROM` 加进工程；
3. 顶层删掉测试音模块、换成 `audio_rom_player`；
4. 上板确认：HDMI 出声、`acr_cts` 正常、无爆音、复位后淡入。

**这一阶段最容易踩的坑**：音频源必须是 48kHz 帧率送进 I2S，否则
`audio_arc_calculate` 算出的 ACR 是错的，HDMI 端会没声音。见
`doc/音频通路说明.md` 第 3 节。

### 阶段 C：音画联动（第 6~8 天）

- `sd_card_bmp` 在提交新图那一拍输出 `audio_track_idx` + 翻转 `audio_track_toggle`；
- 播放器检测到翻转后：20ms 淡出 → 换段 → 20ms 淡入；
- 上板确认 4 段音频与 4 张图一一对应。

### 阶段 D：键控加固与回归（第 9~10 天）

- 连按计数从 1 次改为最多 3 次（加载期间按键不再丢）；
- 轮播间隔参数化 `AUTO_INTERVAL_MS`，默认 3s；
- S6/S7 用例跑通（本机没装仿真器时以 TD 时序报告 + 上板记录为准）。

### 阶段 E：稳定性与交付（第 11~14 天）

- 上板连续运行 30min（阶段 4 再拉到 2h），逐条填测试记录表；
- 资源与时序报告归档；
- 演示视频、报告、PPT 骨架。

### 阶段 3（基础版稳定之后）：音频可视化

- 第一步：`team/waveform_overlay.v` 时域波形（已实现并接在 `osd_overlay` 之后：
  画面左上 x=64/y=16 的 512×72 窗口，显示最近约 32ms 的音频包络）；
- 第二步：32 点基-2 FFT 频谱柱状图（DSP 余量 29/29，1 个 DSP 分时复用）。

## 7. 与《C_工作与学习计划.md》的对齐说明

赛前那份计划（2026-09-27）里有几处和现在的实现不一样，这里说明为什么：

| 原计划 | 现在的做法 | 原因 |
| --- | --- | --- |
| 另起 `key_debounce.v` / `play_ctrl.v` 两个新模块 | 直接在 `sd_card_bmp.v` 里加固（消抖已经是 `key_press_debounce`，状态机也已存在） | 基线里这两块已经在跑且上板验证过，另起一套反而要重做接口，风险更大 |
| 阶段 2 从 TF 卡读 WAV 播放音频 | 先用片内 ROM 存 4 段短讲解 | ROM 方案不用碰 TF 卡扇区布局与 SDRAM 带宽，最快拿到"音画联动"这条扩展；TF 卡音频作为下一步 |
| 需要 B 尽早给"图层叠加接口草案" | 不需要了 | B 的 `osd_overlay` 是流式接口（rgb_in/rgb_out + hs/vs/de），波形层直接串在它后面即可，不用另定坐标查表接口 |
| 担心 12.295MHz ≠ 12.288MHz 导致音画长期漂移 | 已在播放器内部解决 | 素材推进用分数累加器按真实 MCLK 计算，素材恒定按 8.000kHz 播放，LRCK 偏差 0.06% 只影响 ACR 的绝对精度（ACR 仍是 48kHz 帧率算出来的，不漂） |
| 轮播周期 1s/2s 可切 | 参数化为 `AUTO_INTERVAL_MS`，默认 3000ms | 赛题要求"周期可配置"，参数化满足；要现场可切换需再加一个按键，需要 A 先定 key3 引脚 |

**关于红线**（"音频处理方法不能与参考实例相同"）：参考例程是内部生成 I2S 测试音，
本实现改成"片内 ROM 语音 + 按图切段 + 淡入淡出 + 波形可视化"，音频处理方法是不同的。
如果要进一步拉开差距，下一步可以把素材源从片内 ROM 换成 TF 卡 WAV 文件（见音频通路说明第 6 节）。

## 4. 验收标准

| 维度 | 标准 | 验证方式 |
| --- | --- | --- |
| 切图 | 单按/连按/每秒 3 次快按都不丢不跳 | 上板 + 测试记录表 |
| 轮播 | 间隔 3.0s ± 0.3s，可开可关 | 上板掐表 |
| 音频 | 4 段与 4 图一一对应；切图即重播；无爆音；播完循环 | 上板听感 + S6 仿真 |
| 帧率 | I2S LRCK = 48kHz ±0.5%，`acr_cts` ∈ [20000, 30000] | S6 仿真 |
| 稳定性 | 连续切图 100 次无错；连续运行 2h（阶段 4） | 测试记录表 |
| 资源 | LUT ≤ 30%、DSP ≤ 4/29、9Kb BRAM ≤ 40%；音频 ROM 单列（32Kb 12/16） | TD 资源报告 |
| 时序 | SWNS ≥ 0、HWNS ≥ 0、无 PHY-5079 | TD 时序报告 |

## 5. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 片内 RAM 只有约 136KB，装不下长音频 | 讲解只能十几秒 | 用 8kHz/8bit、4×1.5s；要长音频就得走 TF 卡（与 B 协调，风险高） |
| 8kHz 素材直接送 HDMI 会算错 ACR | HDMI 无声 | 播放器内部保持 48kHz 帧率、6× 零阶保持 |
| 音频 ROM 吃满 32Kb BRAM | 后续功能没余量 | 选 48KB 档（12/16 块），留 4 块；参数化可降到 32KB |
| 本机没装 ModelSim | 仿真跑不了 | 用例与一键脚本照交；验证以上板记录为准，装好后一条命令可跑 |
| 顶层是 A 独占文件 | 集成冲突 | C 只提交最小 diff，由 A 合并；接口变更登记到接口约束文档 |

- 提交前缀：`feat:` / `fix:` / `docs:` / `test:` / `chore:`；
