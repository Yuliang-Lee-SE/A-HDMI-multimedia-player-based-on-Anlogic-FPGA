### 1.2 三类违例，性质完全不同

**第一类：SDRAM 数据总线（占违例的绝大多数）**

- 违例组 `clkc[2] -> ext_mem_clk`：**32 个端点全部违例，正好是 DQ[31:0]**，SWNS -6.699 ns
- 违例组 `ext_mem_clk -> clkc[2]`：32 个端点违例，SWNS -2.746 ns
- 关键线索：报告中 `Clock Skew = 4.306 ns`，且综合日志里有

```
PHY-5079 CRITICAL-WARNING: Marked 1 clock net(s) utilize the local routing resources.
  sys_pll_m0/pll_inst.clkc[2] | AL_PHY_PLL | 0/1 | 1 | U3/u2_ram/SDRAM_CLK | true
```

→ **180 度移相时钟走了局部布线，没有占用全局时钟资源，产生 4.3 ns 的时钟偏斜。** 在 8 ns 周期上，光这一项就吃掉一半以上的时间预算。

这是**布线配置问题，不是逻辑问题**，而且有明确的修法。

**第二类：ext_mem_clk 自域内 -0.225 ns（只有 2 个端点）**

- 起点 `frame_read_write_m0/write_buf/wr_to_rd_cross_inst/secondary_addr_o_reg[3]`
- 终点 `frame_read_write_m0/frame_fifo_read_m0/read_req_d2_reg`
- 逻辑级数 **8 级（其中 6 级是 ADDER）**，数据路径延迟 7.973 ns，预算 8 ns

→ 真正的逻辑问题：**一条 6 级加法器链挤在一个 125 MHz 周期里**。这是可以改 RTL 解决的。

**第三类：sd_card_clk 自域内 -0.035 ns（2 个端点）**

- 起点 `sd_card_bmp_m0/bmp_read_m0/file_len_reg[0]`，终点同模块 `state_reg[0]`
- 延迟 9.755 ns，预算 10 ns

→ 几乎踩线，插一级流水即可。

## 2. 基础版的定义（先钉死范围，防止无限膨胀）

### 2.1 必须有的

1. TF 卡读取自己准备的 BMP 图片（640×480、24 位、非压缩）
2. SDRAM 双缓冲，画面稳定，无花屏、无撕裂
3. HDMI 出图，音频出声（沿用例程，不改）
4. key1 手动切图、key2 自动轮播

### 2.2 明确不做的

图片转场、OSD 字幕与图层、图片缩放、亮度对比度调节、音频可视化、分辨率自适应。

**范围冻结规则**：任何人在基础版验收通过之前，不得提交上述高级功能的代码。

### 2.3 验收标准（可量化）

| 维度 | 标准 | 验证方式 |
| --- | --- | --- |
| 时序收敛 | SWNS ≥ 0、HWNS ≥ 0，STA 覆盖率 ≥ 98% | 每次集成的 TD 时序报告 |
| 功能 | 至少 4 张图可切换、可轮播，连续切图 100 次无错 | 上板实测 + 记录 |
| 稳健 | 连续运行 2 小时无异常；空卡、坏图、拔卡不死机 | 压力测试 |
| 资源 | LUT ≤ 30%、BRAM ≤ 40%、DSP 占用不受限 | 资源报告 |

## 3. 时序收敛的三步走（顺序不能颠倒）

### 第 1 步：修移相时钟的布线（最高优先，不改 RTL）

在 IP 工具里重新生成 `sys_pll`，确保 **C2 输出（125 MHz / 180 度）也经过全局时钟缓冲**；或手工在 wrapper 里给 clk2_out 加 `EG_LOGIC_BUFG`。

判据：重新布局布线后，综合日志里不再出现 PHY-5079 关于 clkc[2] 的 CRITICAL-WARNING，且 `clkc[2] -> ext_mem_clk` 那组的 Clock Skew 从 4.3 ns 降到 0.5 ns 以内。

预期收益：-6.699 ns 中的大部分来自这 4.3 ns 偏斜，修好后应该能明显收窄。

### 第 2 步：补 SDRAM 接口约束（不改 RTL）

当前 `timing.sdc` 里明确写着"Input/Output delay 先保持空白"，而 SDRAM 是源同步接口，必须用 IO 延迟约束描述外部往返时间，而不是让工具按两个 PLL 输出的相位差去假设。

要做的事：
1. 给 SDRAM 的 DQ/DM 数据引脚加 `set_output_delay` / `set_input_delay`，参考时钟用输出的 SDRAM_CLK；
2. 复核 `set_clock_groups` 是否需要为 clkc[1] 与 clkc[2] 增加相位关系声明；
3. 重新跑，对比报告。

### 第 3 步：改 RTL 修那两处小违例

- `frame_read_write`：把那条 6 级加法器链拆成两拍（插入一级流水寄存器），代价是增加 1 个时钟的延迟，需要同步检查 `video_delay` 的 21 拍对齐是否仍然成立。
- `bmp_read`：`file_len` 到状态机之间插一级寄存器。

## 4. 分工与边界（按"会不会互相踩"划分）

| 范围 | 归属 | 说明 |

| HDMI 视频通路 | A | |

**流程规则**：
1. 代码必须先通过自己模块的仿真，才允许提合并；
2. 合并到主分支由 A 执行，合并前 A 跑一次"综合 + 时序报告 + 全链路仿真"三件套；
3. 每周固定一次集成节点，集成后打 tag。

## 6. 每次集成的检查清单

- [ ] 仿真：所有模块级 testbench 通过，无 X 传播
- [ ] 综合：无新增 ERROR；HDL-5007 类位宽警告已清零
- [ ] 时序：SWNS ≥ 0、HWNS ≥ 0；无 PHY-5079 类时钟布线警告
- [ ] 资源：LUT / BRAM 占用记录进文档，与上一版对比
- [ ] 上板：四项基本功能（出图、切图、轮播、出声）各验证一次
- [ ] 记录：本次改了什么、影响了哪些模块、有无回退风险
