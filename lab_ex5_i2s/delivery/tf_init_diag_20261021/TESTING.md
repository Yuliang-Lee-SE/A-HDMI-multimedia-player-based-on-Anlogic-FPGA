# A这次只需取得初始化错误码

1. 保留原正常bit、原正常卡/镜像。继续用已核对的同一TF卡，不重新格式化、改名或换图；按原P2接线和RAM下载流程加载 `tf_fat32_32_init_diagnostic.bit`，不写Flash。核对SHA256：`f7a7633b3957a05f0ef81a1c9dbbca347d5782a5ab834f66aee1e30ad49d79c3`。
2. 按KEY1复位，记录到出现F的时间，拍下**整排数码管**。格式为`RCCBBF`，例如`100FFF`表示原因1/CMD0/FF/F，`5092EF`是CMD9 CRC错误示例；示例不是本次实测结果。若只显示F或反而出图，也拍完整现象。可再按一次KEY2，记录是否重试、码是否变化。
3. 反馈完整码/照片、所用bit哈希、卡品牌容量，以及“旧正常bit＋同一卡”的对照。先保留这份诊断证据，不要同时换卡/改素材/改RTL，使对照失去意义。

| R | 位置 |
| --- | --- |
| 1 | 命令响应轮询无有效R1 |
| 2 | 命令回复、R7或OCR不符 |
| 3 / 4 | token超时 / 异常token |
| 5 / 6 | CRC16不符 / 数据尾部异常 |
| 7 / 8 | CSD结构不符 / 容量超范围等 |
| A | 总初始化预算到期 |

CC是十六进制：00=CMD0、08=CMD8、37=CMD55、29=ACMD41、3A=CMD58、10=CMD16、09=CMD9；A原因下FF命令表示尚未进入命令阶段。BB在A原因下是最近完整接收字节，可能不是R1。只见F、其余空白时不能仅凭F确定初始化失败，要同时核对bit身份和后续失败路径。

快照保持到复位或重试；复位/重新初始化会清除。若这次出图，继续记录首图/声音和一次切图即可，先返回结果。实卡速度、多卡、碎片、32张全切换、长时、Flash/掉电仍按原清单另行验收，不因本诊断模型通过而登记正常。
