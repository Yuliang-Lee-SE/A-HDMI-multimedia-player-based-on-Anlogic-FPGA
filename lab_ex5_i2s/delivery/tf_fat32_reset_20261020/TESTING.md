# TF 复位修复候选怎么测

本包修复 TF 与 SPI 复位不同步，**尚待 A 上板确认**。原仓库 bit 已反馈黑屏；原版本地模型也能显示，因此不能把本包称为黑屏已解决。先按下文准备标准图片并做 RAM 测试，保留正常 P2 回退。

需要TF卡。这个版本从卡里的FAT32文件系统读取BMP，**用电脑普通复制图片即可，不需要烧录.img镜像，也不要把bit复制进TF卡**。bit通过之前P2使用的下载器/JTAG流程加载到FPGA的RAM。

## 1. 准备东西

- 原来能跑正常P2的板、电源、下载器、HDMI显示器及音频接线，连接方式不变。
- 一张可用于测试的TF（microSD）卡，以及连接电脑的读卡器。
- 本目录的 `tf_fat32_32_reset_candidate.bit`，以及下文生成的测试图片。

保留原正常P2 bit和原正常卡/镜像，优先另用测试卡。若需要格式化，由持卡者先备份测试卡内容再操作；格式化会清除数据，本说明不要求清空原正常卡。

## 2. 确认卡格式

把测试卡插进电脑读卡器，在“此电脑”查看对应盘的属性，**文件系统必须是FAT32**，不能是exFAT或NTFS。

- 分区形式：普通MBR主分区，或没有分区表、直接是FAT32的卷；不支持GPT/扩展分区。
- 逻辑扇区：512字节。它与“分配单元/簇大小”是两回事。
- 簇大小支持512B～32KiB；已有符合要求的FAT32卡可以先直接用。若给空闲测试卡重新格式化，工具提供时可选32KB分配单元。

如果格式化窗口没有FAT32选项，不要选exFAT凑合用；先换一张已是FAT32的测试卡，或反馈卡容量及格式化窗口信息。首轮不需要专门造碎片，也不需要改原正常卡。

## 3. 准备测试图片

同学已核对的合规图片可以继续使用，无需仅为更换本候选重新格式化或重做卡。以下生成步骤供需要建立可对照测试套时使用。

第一次建议使用仓库脚本生成，避免图片编辑器输出不支持的BMP头。脚本只在电脑上生成普通文件，不访问物理卡；只需Python 3，不需要安装第三方库。

在仓库的 `lab_ex5_i2s` 文件夹打开PowerShell，运行：

```powershell
python tf_player/stage3/prepare_test_assets.py --out tf_test_normal32 --count 32 --case normal
```

若电脑使用 `py` 启动Python，把命令开头的 `python` 换成 `py -3`。若提示输出文件夹已存在，改一个新的输出文件夹名；脚本不会覆盖旧文件。

生成目录里有 `0001.BMP`～`0032.BMP` 和 `PC_MANIFEST.json`。每张BMP为921654字节；JSON记录文件大小和SHA256，留在电脑上用于核对。测试图是彩色纹理，切图时结合画面序号判断，不是正式展品素材。

若以后换自己的图，必须同时满足：640×480、24位、无压缩BI_RGB、正高度bottom-up、40字节BITMAPINFOHEADER，文件长度与头字段相符；不接受额外尾数据。仅改成 `.BMP` 扩展名不算转换。第一轮先用脚本图片排除格式问题。

## 4. 先只复制4张，确认基础链路

把生成的 `0001.BMP`、`0002.BMP`、`0003.BMP`、`0004.BMP` **复制到TF卡根目录**。例如盘符是E时，卡应长这样：

```text
E:\
  0001.BMP
  0002.BMP
  0003.BMP
  0004.BMP
```

不能是 `E:\tf_test_normal32\0001.BMP`；不要把三个测试目录混在卡里。确认扩展名没有重复，根目录没有这次不需要的其他编号BMP，合计不超过32张。不要沿用旧裸扇区写图方式，也不需要复制JSON、WAV、字幕或bit。

复制完成后核对文件大小，需要时按PC_MANIFEST核对SHA256，再从系统安全弹出读卡器。由持板者按原有操作方式将卡装入板上TF卡槽。

## 5. RAM加载并看首图

1. 沿用之前正常P2的板卡接线，显示器选正确的HDMI输入。
2. 下载真正的 `tf_fat32_32_reset_candidate.bit` 文件，不要把GitHub网页另存为bit。可在bit所在目录核对：

   ```powershell
   Get-FileHash .\tf_fat32_32_reset_candidate.bit -Algorithm SHA256
   ```

   结果应为 `1E4F31112784CDF1EE8F9D9F7D50876C1C798226AD06B4BAC2FB2B8A959F397C`。
3. 使用之前P2成功的RAM下载流程加载这个bit，**不写Flash、不擦除Flash**；本轮无需重新综合工程。
4. 按KEY1复位，等待首图完整出现，记录从复位到首图的耗时。首图应是列表第一张，序号01，ID1的原字幕及ROM声音生效。

RAM加载只对本次上电有效，断电后这次配置会丢失；本轮不要求断电后保留新功能，也不修改原Flash内容。

首次首图未出现或显示F时，先按第8节反馈。新 FAT32 码：0起动、1挂载、5装载、6等待共同提交、2空闲、F失败；A/3/4可能很短，不能用旧版“2→4→1”判断成功。请拍下复位后的实际变化和最终停留码，暂不改 RTL 或换中间 bit。

## 6. 按顺序检查

| 操作 | 应当看到/听到什么 |
| --- | --- |
| KEY2下一张，逐张等加载完成 | 序号01→02→03→04，最后再按回01；图像/序号/字幕成功后一起切换，声音随共同提交更新 |
| 固定一张，连续测试KEY3 | 1×整图→2×中心放大、裁掉外围→0.5×居中缩小、图片四周黑边→1×；字幕/序号仍可叠加在画面上 |
| 同一张切换缩放 | 字幕滚动和音轨继续，不从头播放 |
| 加载过程中再按下一张/缩放 | 旧图保持，最终能完成请求并继续操作，不写坏当前画面；不是每次按键都立即换图 |
| KEY4开轮播，再按关闭 | 开启后静止约3秒发起下一张加载，总切换时间还包括实际读卡/缩放；关闭后停留 |

4张首测通过后，再使用完整 `0001.BMP`～`0032.BMP` 测试：

- 4→5：第5张起无中文字幕且静音，这是既定映射，不是声音坏了。
- 31→32，再回01：数量/序号和回绕正确。
- 三档各切换几张、轮播一段时间，观察有无花屏、黑行、撕裂、卡住或串音；记录时长及异常。

## 7. 基础通过后，再测缺号/坏文件/碎片

每次只使用一套测试文件。换套前确认卡上是已备份的测试素材，移除上一套的所有编号BMP，再只复制新一套，安全弹出后复位。不能仅覆盖同名文件：缺号测试会遗留上一套图片，可能超过32张。原正常卡不参与这一步。

**缺号及9999：**

```powershell
python tf_player/stage3/prepare_test_assets.py --out tf_test_missing32 --count 32 --case missing_ids
```

复制该目录BMP替换测试卡上的上一套编号BMP。应按文件编号排序、跳过缺号、末项回到第一项。画面数字是“列表序号”，不一定等于文件编号；例如9999.BMP在这套32张列表中是第32项。

**坏BMP：**

```powershell
python tf_player/stage3/prepare_test_assets.py --out tf_test_bad32 --count 32 --case bad_bmp
```

这套的0002.BMP故意带不支持的压缩字段。先确认0001正常，再按下一张：0002应被拒绝，保留0001画面/序号/字幕/声音，可以出现F提示；再按下一张应恢复到正常0003。

**碎片与读卡恢复：** 基础通过后，再用经PC簇链检查确认的连续/碎片卡分别重复第6节。复制/删除文件不保证实际产生碎片；没有簇链证据时只能记录“普通复制卡通过”，不能写“碎片卡已通过”。中途读卡失败恢复另由持板者在可控条件补测，首轮不必通过拔卡制造故障；未测的项目如实标未测。

## 8. 常见情况与反馈

| 现象 | 先检查 |
| --- | --- |
| 无图/显示F | 卡是否装好、FAT32/分区是否符合、BMP是否在根目录、文件名和数量；优先重新使用脚本生成图。F只是泛化失败提示，不能仅凭F认定坏卡 |
| 电脑能打开图，板拒绝 | 是否32位BMP、top-down、非640×480、其他BMP头或文件长度；JPG/PNG改名不支持 |
| 按键后仍显示旧图 | 可能仍在加载，也可能新文件失败；旧图保持是保护行为。记录是否出现F、等待耗时及目标文件 |
| 第5张以后没有中文/声音 | 正常，只有ID1～4有原字幕/ROM音轨 |
| 恢复卡后仍失败 | 原下一张可触发重试；若bank归属保护导致锁定，用KEY1复位，记录触发过程 |
| 正常P2也没有HDMI/声音 | 先检查沿用的接线、显示器输入和板卡基础状态 |

反馈请附：提交/bit SHA256、卡品牌型号容量、文件系统/簇大小、BMP清单、按键顺序、素材ID/序号/倍率、复位到首图及故障耗时、是否复现，以及含状态显示和声音的照片/视频。连续/碎片、不同卡、长时、RAM、Flash和掉电结果分开写。

需要回退时，用 `../osd_scroll_20261011/osd_scroll_candidate.bit` 并恢复它的原正常卡/素材布局；旧裸扫描P2 bit不保证读取现在普通复制/碎片的新卡。当前仅发布RAM待验证候选，Flash写入和掉电启动应在RAM反馈正常后另行安排。
