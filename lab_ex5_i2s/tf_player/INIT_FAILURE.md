# SD初始化失败诊断（2026-10-21）

以队友最新反馈为准：数码管F，屏幕无画面和声音；队友排查为SD初始化失败，换之前版本bit可以正常运行。小一已确认该次失败是最新复位候选1e4f3111，登记板测失败。因此优先检查读卡初始化，暂不改图片、显示通路或文件数量；不把旧“2→4→1”当本次状态。

F本身是汇总码，既可能是init_error，也可能是后续加载失败。只凭照片不能确认具体命令。首图提交前黑屏/静音符合保护逻辑，不据此另认定HDMI或音频坏了。旧bit正常不证明新版OCR/CSD/CRC/超时流程兼容实卡；不关闭这些检查来消除F，也不因模型通过就否定队友实测。

本轮新增只读诊断：失败时记录原因1位、命令2位（十六进制）、接收值2位，原F留最右，共六位 `RCCBBF`；启动成功时其余五位仍空白。快照保持到复位或重新初始化。总超时使用最后一个完整接收字节，不把移位寄存器中的半字节当回复。跨域同步保持有效信号，额外等待两拍后采样冻结字送原数码管扫描，不接回协议/显示控制。

| 原因R | 含义 |
| --- | --- |
| 1 | 命令响应轮询无有效R1 |
| 2 | R1/R7/OCR与预期不符 |
| 3 | 等待数据token超时 |
| 4 | 收到异常token |
| 5 | 数据CRC16不符 |
| 6 | 数据尾部guard字节异常 |
| 7 | CSD结构/寻址/块长不符 |
| 8 | CSD容量为零、溢出或超当前寻址范围 |
| A | 总初始化预算到期；命令FF表示尚未进入命令阶段 |

命令00=CMD0、08=CMD8、37=CMD55、29=ACMD41、3A=CMD58、10=CMD16、09=CMD9。BB为该失败处接收值；原因A为最近完整字节，未必是R1。示例100FFF是CMD0响应轮询超时，5092EF是CMD9 CRC失败示例，不能套作A实际结果。只有F且其余空白表示没有这类初始化快照，仍要结合bit身份和失败路径区分。

当前修改保持读卡策略、频率、超时、CRC、容量、FAT、完整帧提交、音频映射及原按键。SD读取器与原716e816版逐周期比较全部协议引脚和事务输出；另有实际顶层六位扫描/清除/恢复、SPI37及短回归。剥离明确诊断语句后，SD/调度/顶层其余功能文本与原版一致；这是源码范围审计，不是形式化证明或实板通过。
